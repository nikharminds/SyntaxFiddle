## Why Convert JSON Payloads into Strongly-Typed Apex Classes?

Every Salesforce integration eventually calls an external API and gets JSON back. The lazy path is `JSON.deserializeUntyped()`, casting your way through `Map<String, Object>` structures at runtime. The professional path is a typed wrapper class, and the difference shows up the first time an API changes a field name:

- **Type safety** — field access is checked at *compile time*, not discovered as a runtime `NullPointerException` in production.
- **Readable call sites** — `order.lineItems[0].unitPrice` instead of a tower of casts.
- **Cleaner test classes** — mocks deserialize into the same wrapper, so unit tests assert on typed properties.
- **LWC- and Flow-ready** — `@AuraEnabled` members can be exposed directly to Lightning Web Components.

### JSON.deserialize untyped vs typed Apex: a comparison

```apex
// Untyped: compiles, then fails at runtime, casts everywhere
Map<String, Object> raw = (Map<String, Object>) JSON.deserializeUntyped(json);
List<Object> items = (List<Object>) raw.get('lineItems');
Map<String, Object> first = (Map<String, Object>) items.get(0);
Decimal price = (Decimal) first.get('unitPrice'); // typo here = runtime exception
```

```apex
// Typed: one call, checked at compile time
OrderWrapper order = OrderWrapper.parse(json);
Decimal price = order.lineItems[0].unitPrice; // typo here = compile error
```

| | `deserializeUntyped` | Generated wrapper class |
| --- | --- | --- |
| Field access | Manual casts | Typed properties |
| Errors surface | Runtime | Compile time |
| Testability | Fragile assertions | Typed, refactor-safe |
| Boilerplate | At every call site | Generated once |

## How to Convert JSON to Salesforce Apex: Step-by-Step

### The raw JSON payload

Take a typical integration response — nested objects, an array of line items, mixed value types, and one landmine: a key named `currency`, which is a reserved Apex word.

```json
{
  "orderId": "8015g00000ABCdD",
  "account": {
    "name": "Northern Trail Outfitters",
    "industry": "Retail",
    "annualRevenue": 12500000.75
  },
  "lineItems": [
    { "sku": "GX-1000", "quantity": 3, "unitPrice": 249.99 },
    { "sku": "GX-2000", "quantity": 1, "unitPrice": 899.5 }
  ],
  "currency": "USD",
  "closed": true,
  "contactCount": 142
}
```

### The generated Apex wrapper class

An Apex wrapper class generator turns that payload into compilable Apex — `String`, `Integer`, `Decimal`, `Boolean`, inner classes for nested objects, `List<T>` for arrays, `@AuraEnabled` on members, and a static `parse()` helper:

```apex
public with sharing class OrderWrapper {

    @AuraEnabled
    public String orderId;

    @AuraEnabled
    public AccountWrapper account;

    @AuraEnabled
    public List<LineItemWrapper> lineItems;

    // "currency" is a reserved Apex word — sanitized on generate
    @AuraEnabled
    public String currencyX;

    @AuraEnabled
    public Boolean closed;

    @AuraEnabled
    public Integer contactCount;

    @AuraEnabled
    public static OrderWrapper parse(String json) {
        return (OrderWrapper) JSON.deserialize(json, OrderWrapper.class);
    }

    public class AccountWrapper {
        @AuraEnabled public String name;
        @AuraEnabled public String industry;
        @AuraEnabled public Decimal annualRevenue;
    }

    public class LineItemWrapper {
        @AuraEnabled public String sku;
        @AuraEnabled public Integer quantity;
        @AuraEnabled public Decimal unitPrice;
    }
}
```

### Deserializing with JSON.deserialize

With the wrapper deployed, consuming the API is a single typed call — in an integration service, a batch job, or an LWC controller:

```apex
HttpResponse response = http.send(request);
OrderWrapper order = OrderWrapper.parse(response.getBody());
System.debug(order.lineItems[0].unitPrice); // 249.99
```

The explicit form does the same thing if you prefer it inline:

```apex
OrderWrapper order =
    (OrderWrapper) JSON.deserialize(response.getBody(), OrderWrapper.class);
```

## Handling Edge Cases: Reserved Keywords, Reserved Names & Arrays

Real payloads are never as polite as documentation examples. This is where hand-writing wrappers — and naive generators — fall apart.

### Reserved Apex keywords

Keys like `global`, `class`, `currency`, and `date` are reserved words in Apex and cannot be used as property names. Paste them into a basic generator and you get code that **does not compile**. The converter detects reserved words during generation and sanitizes them into valid identifiers — `currency` becomes `currencyX` — so the emitted class always compiles, and the rename is flagged in the output for review.

### Nested objects, arrays, and nulls

To convert nested JSON to Apex correctly, the generator maps structure mechanically:

- Nested objects become **inner classes** (`AccountWrapper` inside `OrderWrapper`).
- Arrays of objects become `List<LineItemWrapper>`; arrays of primitives become `List<String>` and friends.
- JSON `null` values deserialize into `null` members — leave fields nullable rather than guessing defaults.
- Apex property matching is case-insensitive, and the generator preserves your original key casing so round-tripping stays predictable.
