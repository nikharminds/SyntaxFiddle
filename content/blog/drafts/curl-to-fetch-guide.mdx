Every API doc on the internet speaks cURL. It is the lingua franca of HTTP examples — but
when it is time to call that endpoint from a web app or a Node script, you need to convert
the cURL command to JavaScript. The translation is mostly mechanical: a handful of
flag-to-option mappings cover practically every command you will meet.

## cURL to fetch: the basic mapping

Here is a typical documented request:

```bash
curl https://api.example.com/users?page=2&limit=20
```

And its JavaScript equivalent:

```javascript
const response = await fetch(
  "https://api.example.com/users?page=2&limit=20",
);

const users = await response.json();
```

Query strings pass straight through — no serialization needed unless you build them
dynamically:

```javascript
const params = new URLSearchParams({ page: "2", limit: "20" });
const response = await fetch(
  `https://api.example.com/users?${params}`,
);
```

## Flag-to-option cheat sheet

| cURL flag            | fetch equivalent                                   |
| -------------------- | -------------------------------------------------- |
| `-H "Key: value"`    | `headers: { Key: "value" }`                        |
| `-d 'raw body'`      | `body: "raw body"`                                 |
| `-d @file.json`      | `body: await readFile("file.json", "utf8")` (Node) |
| `-X POST`            | `method: "POST"` (implied by a body)               |
| `-u user:pass`       | `Authorization: "Basic " + btoa("user:pass")`      |
| `-L`                 | Default behavior — redirects are followed          |
| `--max-time 10`      | `AbortSignal.timeout(10_000)`                      |
| `-b "session=abc"`   | `headers: { Cookie: "session=abc" }` or credentials |

## Sending a JSON POST request with fetch

The most common conversion is a JSON POST. In cURL:

```bash
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tok_123" \
  -d '{"name": "Ada Lovelace", "role": "admin"}'
```

In fetch, headers become an object and the body a `JSON.stringify` call:

```javascript
const response = await fetch(
  "https://api.example.com/users",
  {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: "Bearer tok_123",
    },
    body: JSON.stringify({
      name: "Ada Lovelace",
      role: "admin",
    }),
  },
);

if (!response.ok) {
  throw new Error(`HTTP ${response.status}`);
}
const created = await response.json();
```

## Handling errors properly

cURL treats any completed HTTP exchange as success; fetch does too — a 500 response does
**not** reject the promise. Build the check in:

```javascript
async function apiFetch(url, options) {
  const response = await fetch(url, options);
  if (!response.status) throw new Error("Network error");
  if (!response.ok) {
    const detail = await response.text();
    throw new Error(`HTTP ${response.status}: ${detail}`);
  }
  return response.json();
}
```

## cURL vs fetch: edge cases that bite

- **Credentials.** cURL sends basic auth eagerly; in the browser, `fetch` only sends cookies
  cross-origin when you pass `credentials: "include"`.
- **CORS.** A cURL command from your terminal has no origin — the same request from a page
  does. Preflights and allow-lists apply only in the browser.
- **Timeouts.** fetch has no built-in timeout; pair it with `AbortSignal.timeout()` (or an
  `AbortController`) instead of relying on framework defaults.
- **Form data.** Pass a `FormData` object as the body and let the browser set the
  content type — hand-building the multipart boundary is a classic bug.
